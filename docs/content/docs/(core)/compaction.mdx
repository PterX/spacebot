# Compaction

Long conversations need bounded context. Spacebot compacts history in the background, so a channel can keep responding while older context is prepared for its next turn.

The compactor is programmatic. It measures channel context after each turn and schedules LLM work only when a summary or chronicle checkpoint is needed.

## Modes

`compaction.mode` selects one of two history strategies.

| Mode | Behavior |
| --- | --- |
| `rolling` | Replaces older transcript spans with summaries at the head of the live history. |
| `chronicle` | Cuts append-only checkpoints over contiguous transcript ranges and preserves them as durable session history. |

Rolling mode is appropriate for short-lived conversations. Chronicle mode is for sessions that need to retain a navigable record over days or weeks. Switching back to rolling stops new checkpoint creation, but previously committed checkpoints remain available so trimmed context is not lost.

## Thresholds

Three thresholds protect the context window in either mode.

| Threshold | Default | Action |
| --- | --- | --- |
| Background | 80% | Schedule normal compaction. |
| Aggressive | 85% | Compact a larger historical span. |
| Emergency | 95% | Remove old history synchronously without an LLM call. |

Only one compaction runs per channel. Emergency truncation records a marker in the history so the channel can account for the lost span.

## Rolling Summaries

In rolling mode, the compaction worker removes an older range from live history, summarizes it, and inserts the summary at the start of the channel history. The worker can also save durable memories before that range leaves the prompt.

The channel does not wait for the worker. It continues using the remaining transcript and receives the new summary on a subsequent turn.

## Session Chronicles

Chronicle mode creates an append-only checkpoint whenever the transcript grows past its message or token interval. Each checkpoint records the transcript range it covers and summarizes only that range. Checkpoints are persisted in SQLite, survive restarts, and maintain contiguous coverage of the session.

The prompt renders a bounded chronicle view:

- Recent checkpoints appear in full.
- Older checkpoints collapse under the configured token budget.
- Older level-zero checkpoints roll up into coarser summaries when the threshold is reached.
- Rollups retain their source checkpoint and transcript-range provenance.

The channel can list its checkpoints, open a summary, or ask a branch to expand a raw transcript range when a checkpoint is insufficient. Portal renders the same checkpoint records inline in its timeline.

See [Chronicles](/docs/chronicles) for the user-facing model and operations.

## Configuration

```toml
[defaults.compaction]
mode = "chronicle"
background_threshold = 0.80
aggressive_threshold = 0.85
emergency_threshold = 0.95

[defaults.compaction.chronicle]
interval_messages = 40
interval_token_fraction = 0.12
recent_window_hours = 24
max_recent = 8
max_older = 12
context_token_budget = 2000
expand_message_limit = 100
max_messages_per_checkpoint = 400
rollup_threshold = 12
rollup_batch = 8
```

The `context_window` setting determines the denominator for threshold checks. Set it to the actual context window of the model serving the channel.

## Implementation

- `src/agent/compactor.rs` monitors context and schedules compaction.
- `src/conversation/chronicle.rs` stores checkpoints, coverage, and rollup provenance.
- `src/agent/chronicle.rs` renders the bounded prompt view and branch expansion context.
