# Cortex

The cortex is the per-agent background coordinator. It maintains system state that should not belong to a user channel: database hygiene, association work, circuit-breaker observations, and process registry cleanup.

It does not author the knowledge section of every prompt. Channels render a deterministic view of the memory store at turn time. It also does not cancel workers or branches. Each execution path owns its wall-clock timeout and terminal state.

## Responsibilities

### Memory Maintenance

The cortex schedules maintenance passes over the memory graph:

- Decay reduces importance for stale, non-identity memories.
- Pruning removes memories below the configured age and importance floor.
- Association passes create graph links for related memories.
- Write-time consolidation handles likely duplicates when memory is saved, before periodic maintenance is needed.

### Health Signals

The cortex observes process events and tracks structured tool failures for circuit breakers. It also prunes dead process-control registrations. A circuit breaker records repeated failures without treating an event stream as authority over a worker's lifecycle.

### Dormant Mode

Agents can run with the cortex in `dormant` mode. Periodic loops remain stopped until an external wake requires work. This is useful for fleets where most agents are idle.

## Memory Context

Channels receive a bounded, deterministic render of the memory store. The render groups the most useful memories by type and includes active goals. It reads current SQLite state directly, so it is fresh on every turn and does not require a synthesis call.

Targeted memory retrieval still goes through a branch. A branch can search the graph, inspect supporting context, and return a concise conclusion to the channel.

See [Memory](/docs/memory) for storage and recall behavior.

## Configuration

```toml
[defaults.cortex]
mode = "active"
tick_interval_secs = 30
worker_wall_clock_timeout_secs = 600
circuit_breaker_threshold = 3
maintenance_interval_secs = 3600
maintenance_decay_rate = 0.05
maintenance_prune_threshold = 0.1
maintenance_min_age_days = 30
maintenance_merge_similarity_threshold = 0.95
memory_render_max_words = 500
consolidation_partition_cap = 200
consolidation_near_duplicate_threshold = 0.95
```

`worker_wall_clock_timeout_secs` bounds an individual worker run. Cron jobs can define their own timeout and otherwise use the agent's cron default.

## Cortex Chat

The dashboard exposes an administrative cortex chat for inspection and operations. It has embedded architecture context, redacted live configuration, and tools for inspecting runtime state. It is not part of a user conversation or the normal autonomy execution path.
