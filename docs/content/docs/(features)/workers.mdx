# Workers

Workers execute work while channels remain available for conversation. They run shell, file, browser, MCP, and coding tools against a focused task, then report an explicit outcome.

## Context

A delegated worker starts with the task and the relevant channel context. For a recent conversation, this may be recent transcript history. For a long-running session, Spacebot passes the bounded chronicle view instead of the entire transcript.

This preserves the user intent behind delegated work without turning the worker into another long-lived channel. A task execution plan can additionally require skills, a project, and a worktree mode.

## Execution Models

| Worker | Use |
| --- | --- |
| Built-in | Rig worker with Spacebot's shell, file, browser, web-search, and configured MCP tools. |
| OpenCode | Persistent coding-agent subprocess with its own codebase and language tooling. |

Workers can be one-shot or interactive. Interactive workers retain their own working history and accept channel follow-up through `route`.

## Lifecycle

Workers report progress through `set_status` and must signal a terminal outcome. Their lifecycle converges on one durable terminal record, which drives task settlement, channel retriggers, and live process displays.

The worker's own wall-clock timeout bounds a run. Cancellation and completion use the same terminal-state path so a late completion cannot overwrite a cancellation or failure.

## Task Execution

Tasks can declare an execution plan:

- Worker type: built-in or OpenCode.
- Project and repository.
- Worktree mode: root checkout, an existing worktree, or a worktree created for the task.
- Required skills, injected as execution requirements rather than suggestions.

See [Tasks](/docs/tasks) for plan resolution and dependency gates.

## Tools and Isolation

Workers receive task tools, not channel reply tools. The available set depends on instance configuration:

| Tool | Purpose |
| --- | --- |
| `shell` | Run commands with a configured timeout. |
| `file` | Read, write, and list workspace files. |
| `browser` | Drive Chrome when browser automation is enabled. |
| `web_search` | Search the web when configured. |
| `mcp_*` | Tools discovered from configured MCP servers. |
| `set_status` | Publish progress and terminal outcomes. |

Shell and file access stay inside the configured workspace boundary. System credentials are not inherited by subprocesses. Tool credentials are injected only when their secret category permits it. See [Sandbox](/docs/sandbox) and [Secrets](/docs/secrets).

## Configuration

```toml
[defaults]
context_window = 128000

[defaults.routing]
worker = "anthropic/claude-haiku-4.5-20250514"

[defaults.routing.task_overrides]
coding = "anthropic/claude-sonnet-4-20250514"

[defaults.cortex]
worker_wall_clock_timeout_secs = 600
```

Use [Configuring Channels](/docs/configuring-channels) to control delegated worker context per conversation.
